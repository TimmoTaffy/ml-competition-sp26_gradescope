## Reproducibility Boundary

There are two different reproducibility questions:

| Question | Status |
| --- | --- |
| Reproduce the submitted portfolio from code and data | Yes |
| Retrain the final selected two models from scratch | Yes |
| Re-evaluate the frozen 12 candidates with live-style validation | Yes |
| Re-run portfolio fine-tune on those 12 candidates | Yes |
| Recreate every early broad/fine intermediate table exactly as originally produced | No, bulky obsolete intermediate outputs were deleted |

This is acceptable for the submission workflow because the final portfolio is
reproducible from retained configs, feature sets, raw data, and training code.
If the report discusses the research process, describe the top12 as the
retained candidate set from structured research-family search, then focus
reproduction on the frozen candidate configs and final live-style validation.

## Historical 33 To 12 Selection

The older research route used fixed-block portfolio validation before the
project switched to strict live-style validation.

The sequence was:

1. Run broad research-family search over structured candidates.
2. Take the top `33` candidates from the broad leaderboard.
3. Re-run those `33` candidates with a denser fine-stage fixed-block portfolio
   grid.
4. Retain the top `12` candidates for later model-pair and portfolio work.
5. Re-evaluate and retune those retained candidates with the current
   live-style 3/7/13 workflow.

The broad search space was:

```text
5 ranking families x 4 feature-count pairs x 3 model presets = 60 candidates
```

The broad portfolio grid was coarse:

```text
weights:       1.0,0.85,0.7,0.55,0.4,0.25,0.1,0.0
top_k:         30,40,50,70,100
internal caps: 0.03,0.05,0.08,0.10
risk filter:   on/off
weighting:     rank/equal
```

The fine-stage grid was denser:

```text
weights:       0.00 to 1.00 in 0.05 steps
top_k:         30,35,40,45,50,60,70,80,100
internal caps: 0.03,0.04,0.05,0.06,0.08,0.10
risk filter:   on/off
weighting:     rank/equal
```

That old fixed-block score was:

```text
0.45 * mean_portfolio_excess_rank
+ 0.25 * worst_day_rank
+ 0.20 * hit_rate_rank
+ 0.10 * mean_rank_ic_rank
```

This old score was useful for narrowing the search space, but it is no longer
the final selection criterion because fixed-block 5-day forward targets can
overlap validation boundaries.

The retained `candidate_family_lookup.csv` keeps the historical top-33 list:

```text
experiments/research_families/fine_tune_top12/candidate_family_lookup.csv
```

The first 12 rows of that file are the retained top12 candidate families used
by the current workflow.

What is not preserved: the full old broad/fine grid result tables and the old
fixed-block leaderboard files. Re-running the broad/fine search today is
possible from code, but it may not produce byte-identical results because the
data matrix, features, and code have evolved.

## Reproduce The 12-Candidate Live Validation

After the data and feature matrix are rebuilt, run:

```bash
conda run -n ml26s python live_walk_forward_validation.py \
  --num-windows 13 \
  --window-length 5 \
  --out-dir experiments/research_families/fine_tune_top12/live_walk_forward_13w \
  --skip-existing
```

This retrains the relevant candidate models from scratch at each historical
entry date using the retained configs and feature sets.

The old derived 3-window, 7-window, and 2/5/10 diagnostic directories were
deleted because the current phase2 blend tuner reads the four retained 13-window
anchor runs directly.

## Reproduce Phase1

Phase1 used the rounded `stable_compact_current` candidate only:

```bash
conda run -n ml26s python make_submission.py \
  --config configs/ensemble_phase1.json \
  --as-of 20260503 \
  --out submissions/submission1.csv

conda run -n ml26s python validate_submission.py submissions/submission1.csv
```

Before running those commands from scratch, rebuild data with `--end 20260503`
and train the current general/short-history models as shown in
`PHASE_REPRODUCTION.md`.

## Reproduce The Phase2 Blend

```bash
conda run -n ml26s python tune_portfolio_blend_current_capacity.py \
  --out-dir experiments/portfolio_blend_current_capacity \
  --write-best-submission \
  --submission-out submissions/submission2.csv \
  --scores-out submissions/submission2.scores.csv

conda run -n ml26s python validate_submission.py submissions/submission2.csv
```

## Reproduce The Portfolio Fine-Tune

```bash
conda run -n ml26s python live_portfolio_fine_tune_3_7_13.py \
  --out-dir experiments/research_families/fine_tune_top12/live_portfolio_fine_tune_3_7_13 \
  --source-run experiments/research_families/fine_tune_top12/live_walk_forward_13w \
  --skip-existing \
  --progress-every 50000
```

Then run the rounded-parameter and neighborhood audit:

```bash
conda run -n ml26s python audit_portfolio_param_robustness.py \
  --out-dir experiments/research_families/fine_tune_top12/live_portfolio_fine_tune_3_7_13/robustness_audit \
  --skip-existing
```
